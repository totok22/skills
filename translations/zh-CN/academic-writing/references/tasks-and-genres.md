# 任务、体裁、翻译与长文

说明不同体裁的写法重点、中英互译、基于材料起草、审稿回复以及长文和笔记整理的操作方法。

## 目录

1. 体裁与结构
2. 中英互译
3. 基于材料起草
4. 审稿回复
5. 长文与笔记整理

## 1. 体裁与结构

按文稿实际论证和目标期刊习惯决定结构。`polish` 阶段不强行重排整篇结构。

- **专业期刊与学位论文（IEEE、ACM、Elsevier、Springer 等）：** 通常采用先收窄后展开的漏斗结构——由大问题收束到具体缺口，再写方法与结果，最后在开头承诺的范围内收尾，不夸大结论。
- **综合顶刊（*Nature*、*Science* 等）、摘要与技术报告：** 通常先把主要结果、判断或状态放前面，再展开条件和依据。

| 体裁 | 主要重点 | 常见失误 |
| --- | --- | --- |
| **Abstract（摘要）** | 研究问题、方法、关键定量结果、有边界的结论 | 编造创新性、用空泛形容词替代数据、与正文重点脱节 |
| **Introduction（引言）** | 问题背景、公允梳理前人工作、明确缺口、清晰目标 | 编造引用、不公允贬低前人、把本文目标埋在后面 |
| **Methods（方法）** | 可复现性、先后顺序、装置、参数、单位、排除标准、工况 | 漏掉边界条件、为改主动语态编造执行者、写理想流程而非实际做法 |
| **Results（结果）** | 直接对比、数值、单位、分母、不确定度、变化方向 | 把未证实机理混进实测结果、隐去阴性或失败结果 |
| **Discussion（讨论）** | 基于结果的解释、与前人对比、具体局限性 | 把相关写成因果、过度防御、原样重复 Results、套话式局限性 |
| **Figure / Table Caption（图表标题）** | 自洽说明变量、图例、单位、样本量与测试条件 | 解释图中并未呈现的趋势或原因 |
| **Cover Letter（投稿信）** | 与期刊定位的契合度及基于材料的贡献 | 编造独家投稿、伦理审批、共同作者确认或吹捧 |
| **技术 / 工程报告** | 结论、边界条件、安全裕度、设计依据、验证状态 | 混淆设计意图与实测结果、隐去失败记录或待办事项 |
| **学习 / 技术笔记** | 按主题逻辑排布、保留全部细节、推导步骤完整 | 保留聊天轮次碎片、为变短删掉边界条件、把公式推导删成空话 |
| **一般专业写作** | 读者需要知道的结论或动作、平实语气 | 照搬僵硬期刊腔或套论文模板 |

系统或模块设计文档可默认按 **职责与目标 → 已实现流程 → 接口或协议 → 故障处理 → 验证与待办** 组织；测试报告和故障分析按实际需要调整。已验证行为与待标定、未确认参数及后续计划始终分开。

## 2. 中英互译

按分句和段落翻译，使译文在目标学科中自然地道，同时忠实保留原文逻辑和语气轻重。

1. **做好中英句法转换：**
   - **中译英：** 中文常以逗号串接多个分句并隐含因果、条件或先后（如 `温度升高，反应加快，产率提高`）。译为英文时整理成主从清晰的句式，并准确标出原文真实的逻辑关系；原文只表先后时不要脑补因果，也不要全用 `and` 硬连。注意避免悬垂修饰（`Using this method, the SNR improved` → `With this method, the SNR improved` 或 `Using this method, we improved the SNR`）和叠床架屋的 `of` 链条。
   - **英译中：** 去掉生硬翻译腔，少用多余的“被”、空泛动词（`进行/做出/实现`）和过长的多层“……的……的”定语，按中文习惯组织成“条件或时间 → 主体 → 动作与结果”。
2. **保留精度与限定。** 保留全部限定词、负面发现、对比对象、主语关系、不确定度和先后顺序；不额外加解释，也不漏掉限定。
3. **保护术语与标记：**
   - 优先按用户术语表翻译，其次采用学科通行译名；同一概念全篇统一，确有歧义时在简短附注中说明。
   - 保持 LaTeX 数学公式、引用与交叉引用命令（`\cite*`、`\ref`、`\eqref`、`\cref`）、代码块、行内代码、URL 和引用键原样不变。
   - 除非明确要求单位换算，否则保持数值和单位不变，并用 `scripts/check_fidelity.py` 校验。
   - 不翻译代码标识符或引用键，不在成品中残留未翻译的原文片段。

## 3. 基于材料起草

1. **动笔前先把材料分四类：** (a) 已验证的事实、数据和引用；(b) 假设或设计意图；(c) 计划中或未验证的工作；(d) 缺失的必要信息。
2. **只写材料里有的事实。** 不编造样本量、p 值、仪器型号、超参数、文献引用、DOI、伦理审批或创新性宣称，也不从风格示例借用事实。
3. **缺什么就标什么。** 凡缺少必要细节的位置，标出 `[作者待确认：<缺失项>]`（中文）或 `[Author to confirm: <missing item>]`（英文）。
4. **分清推论与实测。** 连接已有事实的逻辑推演写明是推理或解释，不写成实测结果。

## 4. 审稿回复

回复中每一句关于“已修改”的说法都要能在修订稿里查到：

1. **逐条原样编号。** 把包含多个子问题的审稿段落拆成独立编号（`R1.1`、`R1.2`、`R2.1`），保留原话，不篡改或弱化批评，也不编造审稿意见。
2. **标明修改位置。** 给出确切位置（`Section X.Y` 或 `file:line`）并引用改后的原句；若看不到修订稿或 diff，如实注明位置依据用户描述。
3. **坦诚处理未改项与冲突要求。** 拒绝修改、超出范围或缺少数据的条目，写明未改状态和简明事实理由（必要时说明已在文中添加局限性），不悄悄跳过。两位审稿人要求冲突时，给双方一致的理由并相互说明。
4. **字数受限时压缩措辞，不删条目。**

常用条目格式：
- **审稿意见（`R1.1`）：** `<审稿人原话>`
- **回复：** `<基于证据的直接答复>`
- **稿件修改：** `<章节/行号 + 修改后原句，或 [作者待确认：...] / 未修改（理由）>`

## 5. 长文与笔记整理

- **先通读再修改。** 读相邻章节或全文提纲，顺手记三项内容：
  1. **术语与缩写：** 标准术语、符号及首次定义位置（双语中文笔记或论文里，关键术语只在首次出现时标注 `中文术语 (English Term, ABBR)`）。
  2. **关键数据和结论：** 核对 Abstract、Methods、Results、Discussion、表格和图注中的数值、单位、分母和范围，避免前后矛盾。
  3. **章节分工与编号：** 保持各节职责清晰，检查标题、列表、图表和公式编号连续无重跳。
- **合并重复笔记时不丢细节。** 合并多轮对话导出或重复段落时，去掉轮次顺序，按主题重新组织；以最完整的一份为底稿，把其他段落里的独有细节合入同一位置。运行 `check_fidelity.py` 时可加 `--allow-dedup`，避免合理合并重复数值时误报。
- **保护整篇文件并说明范围。** 不用局部摘录覆盖整篇文稿；若只提供了节选，简短说明哪些跨章节核对无法完成。
